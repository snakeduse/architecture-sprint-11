# Описание задания 1

Ниже приводится выполнение пунктов задания 1. Описание идет в логическом порядке от проблемы к решению.

## Проблемные места текущей архитектуры

- Устаревшие технологии:
  - **DWH на SQL Server 2008**(Высокий приоритет):
    - Низкая производительность при обработке сотен терабайт данных;
    - Отсутствие поддержки современных функций (например, горизонтальное масштабирование, индексация для аналитических запросов);
  - **Power Builder**(Средний приоритет):
    - Устаревший интерфейс для операторов клиник, сложность интеграции с новыми системами;
  - **Apache Camel**(Высокий приоритет):
    - Не справляется с асинхронной обработкой данных от новых бизнесов (фармацевтика, электроника);
    - Отсутствие поддержки событийно-ориентированной архитектуры;
- Медленная генерация отчетов (Низкий приоритет);
- Все сервисы зависят от DWH (Низкий приоритет).

## Архитектура системы через год

Ниже показана архитектура системы "Будущее 2.0" через год.

![alt text](./diagrams/ToBe.png)

**Портал самообслуживания** —  Веб-интерфейс для бизнес-пользователей, позволяющий создавать отчеты, управлять данными и визуализировать аналитику. Так же имеет админ-панель, где администраторы могут настраивать права;
1. **Общая шина данны (Kafka)** — заменяет устаревшую шину на Apache Camel. Обеспечивает асинхронное взаимодействие между сервисами.
2. **BI-система** - Визуализация данных, генерация отчетов и дашбордов;
3. **Data Lakehouse** - хранилище для разных типов данных: сырые данные (медицинские снимки, логи, события Kafka), структурированные данные (бывшие данные DWH - финансы, инвентаризация, персонал), агрегаты (готовые метрики для аналитики);
4. **ИИ-сервисы** - Анализ медицинских снимков и генерация диагнозов;
5. **Финтех-сервисы** - Обработка финансовых операций;
6. **Брокер сообщений (Kafka)** - Асинхронная передача данных между компонентами;
7. **Внутренние сервисы** - Управление клиникой и персоналом.

На схеме не показано, но можно оставить старый DWH в качестве источника архивной информации,
которая должна будет со временем перенестись в Data Lakehouse.
